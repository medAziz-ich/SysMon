Agent Boot & Auto-Registration Flow
Sequence from agent startup to first successful metric delivery, including the one-time registration handshake.
sequenceDiagram participant M as main.c participant R as auto_register() participant S as sender_thread participant Q as queue.c (SQLite) participant C as collector_thread participant SRV as Server /register participant INGEST as Server /ingest M->>M: load_config(config.json) alt No auth_token in config M->>R: auto_register(config_path) R->>SRV: POST /register {agent_name, secret} SRV-->>R: 201 {api_key} R->>R: auth_token = api_key R->>M: write api_key back to config.json end M->>Q: queue_init("/var/lib/sysmon-agent/queue.db") M->>C: pthread_create(collector_thread) M->>S: pthread_create(sender_thread) M->>M: pthread_create(log_tailer × N) loop every interval_seconds C->>C: get_cpu, get_ram, get_disk, update_network, get_service_status C->>Q: queue_enqueue(JSON payload) Q-->>C: signal queue_cond end loop sender loop S->>Q: queue_dequeue(&row_id, &retry, &first_attempt) Q-->>S: payload S->>INGEST: POST /ingest Authorization: Bearer token alt HTTP 2xx INGEST-->>S: 202 accepted S->>Q: queue_delete(row_id) else HTTP 401 token rejected INGEST-->>S: 401 S->>SRV: POST /register re-register SRV-->>S: 201 new api_key S->>Q: queue_update_retry(row_id, 0) else HTTP 429 rate limited INGEST-->>S: 429 S->>S: sleep(60s) else Network error / 5xx S->>Q: queue_update_retry(row_id, retry+1) S->>S: exponential backoff (5s → 120s) end end

Alert Pipeline
How a metric ingest triggers alert evaluation, notification dispatch, and state resolution.
sequenceDiagram participant INGEST as /ingest endpoint participant AE as AlertEngine participant DB as SQLite participant EMAIL as SMTP participant HOOK as Webhook INGEST->>DB: INSERT INTO metrics INGEST->>AE: threading.Thread(check_alerts, hostname, cpu, ram, services) AE->>DB: SELECT host_config (cpu_threshold, ram_threshold, monitoring) DB-->>AE: thresholds AE->>AE: _push_history(hostname, cpu, ram) alt CPU > cpu_threshold AE->>DB: SELECT alert_history (cooldown check) DB-->>AE: not in cooldown AE->>DB: INSERT INTO alert_history (active) AE->>EMAIL: _send_email() [thread] AE->>HOOK: _send_webhook() [thread] else CPU ≤ threshold AE->>DB: UPDATE alert_history status=resolved end alt CPU spike detected (rate-of-change) AE->>DB: INSERT alert cpu:spike AE->>EMAIL: send spike email [thread] AE->>HOOK: send spike webhook [thread] end alt CPU > thr AND RAM > thr (combined) AE->>DB: INSERT alert combined:cpu+ram (critical) AE->>EMAIL: send critical email [thread] AE->>HOOK: send critical webhook [thread] end loop For each service in payload AE->>DB: SELECT service_state (prev status) DB-->>AE: prev_status AE->>DB: UPSERT service_state (new status) alt Service went DOWN (active→failed) AE->>DB: INSERT alert service:down (critical) AE->>EMAIL: service down email [thread] AE->>HOOK: service down webhook [thread] else Service RECOVERED (failed→active) AE->>DB: UPDATE alert service:down → resolved AE->>DB: INSERT alert service:up (info) end end
